Engineer: Kiro (AI Lead Engineer)

--------------------------------------------------------------------------------
OBJECTIVE
--------------------------------------------------------------------------------

Implement conversational reference resolution so AB can track entities across
turns and resolve pronouns (he/she/it/they/him/her/them/this/that/these/those)
and natural-language references (the company, the person, the city, etc.) to
the correct entity without user disambiguation.

Example:
    Turn 1: "Tell me about Elon Musk."
    Turn 2: "Where was he born?"       → resolved: "Where was Elon Musk born?"
    Turn 3: "When did he start Tesla?" → resolved: "When did Elon Musk start Tesla?"

--------------------------------------------------------------------------------
TASKS COMPLETED
--------------------------------------------------------------------------------

[1] CREATED — core/entity_tracker.py
    Class: EntityTracker
    Wraps EntityRegistry with turn-awareness.

    Per-entity metadata tracked (stored in Entity.metadata):
        _tracker_first_turn    — turn number when first mentioned
        _tracker_last_turn     — turn number of most recent mention
        _tracker_frequency     — total mention count
        _tracker_active        — True while within the recency window

    Supported entity types: person, organization, place, object, event, concept

    Key public API:
        advance_turn()                 — increment turn counter
        end_turn()                     — signal end-of-turn processing cycle
        record_entity(name, type, ...) — register/refresh an entity
        get_focus()                    — most recently mentioned entity
        get_focus_by_type(type)        — most recent entity of a given type
        get_active()                   — entities within the recency window
        get_all()                      — all tracked entities
        find(text)                     — lookup by name or alias
        rank_candidates(list, pronoun) — rank by recency + frequency + type + confidence
        reset()                        — clear all state
        to_dict() / from_dict()        — serialisation round-trip

    Supporting class: TrackedEntity — read-only snapshot view of one entity.

[2] CREATED — cognitive/reference_resolver.py
    Class: ReferenceResolver
    Standalone resolver; does NOT depend on Thought objects or the pipeline.

    Supported pronoun references (11 total):
        he, she, they, it, this, that, those, these, him, her, them

    Supported natural-language references (20+ phrases):
        the company / the organisation / the business / the firm
        the person / the individual / the man / the woman
        the city / the place / the location / the country / the region / the town
        the event / the occasion
        the thing / the object
        the concept / the idea / the topic

    Resolution algorithm:
        1. Detect reference words in input text
        2. Determine grammatical type preference (person pronoun → prefer person)
        3. Collect active candidates from EntityTracker
        4. Rank using EntityTracker.rank_candidates()
        5. Compute confidence (base confidence − recency penalty − ambiguity penalty)
        6. >= AUTO_RESOLVE_THRESHOLD (0.65): auto-rewrite
           < CLARIFICATION_THRESHOLD (0.40): ask for clarification
           between: tentative rewrite

    Returns: ResolutionResult dataclass with:
        resolved_text, original_text, referent (TrackedEntity or None),
        confidence, needs_clarification, clarification_question,
        reference_words_found, was_resolved()

[1] CREATED — token_budget.py  (project root, 339 lines)

    ResponseCategory (enum, 7 values):
        GREETING           → 128  tokens
        SHORT_FACTUAL      → 256  tokens
        NORMAL_CONV        → 512  tokens
        REASONING          → 1024 tokens
        LONG_EXPLANATION   → 2048 tokens
        LARGE_REPORT       → 4096 tokens
        VERY_LARGE         → 8192 tokens

    TokenBudgetConfig (dataclass):
        budgets          — per-category token limits (all in config, none hardcoded)
        provider_max     — absolute ceiling (default 4096, conservative for credit tiers)
        fallback_budget  — retry budget after provider rejection (default 512)
        safe_default     — used when category is unknown (default 512)
        validate()       — raises ValueError on inconsistent configuration

    BudgetEstimate (dataclass):
        category, max_tokens, estimated_prompt_tokens, reasoning list, to_dict()

    TokenBudgetManager:
        estimate(prompt, intent) — classifies request by intent label first,
            then by keyword detection (report/reasoning keywords), then by
            prompt-length heuristic. Returns the smallest practical budget,
            clamped to provider_max.
        fallback_budget()        — safe retry value
        provider_max()           — absolute ceiling accessor
        safe_default()           — safe-default accessor

    Module-level helpers:

PART A — Adaptive Cloud Brain

ProviderRegistry (provider_registry.py)
    Runtime registry of ProviderProfile objects.
    Built-in profiles: openrouter, anthropic, openai, ollama.
    Each profile describes: supported_features (ProviderFeature enum),
    context_window, max_output_tokens, default_output_tokens,
    supports_retry, rate_limit_rpm, known_restrictions, models.
    API: register, get, require, remove, all_providers,
         supports_feature, providers_with_feature, find_model.

TokenEstimator (token_estimator.py)
    Estimates max_tokens from prompt size, complexity, category, provider ceiling.
    Categories: GREETING, SHORT_FACTUAL, CONVERSATIONAL, REASONING,
                LONG_EXPLANATION, LARGE_REPORT, VERY_LARGE.
    Resolution pipeline: caller-supplied category → intent label →
    report keywords → reasoning keywords → complexity score → prompt length.
    Complexity scoring: multi-step connectives, question clusters,
    reasoning keywords, long prompt signal.
    All limits in EstimatorConfig — zero hardcoding in logic.

RequestValidator (request_validator.py)
    Four checks before dispatch:
        1. request_size     — prompt tokens vs context window
        2. provider_compat  — required features vs supported features
        3. model_availability — model in known list
        4. token_budget     — max_tokens vs provider ceiling
    Returns ValidationReport with per-issue Severity (INFO/WARNING/ERROR).
    Passes when no ERROR-severity issues found.

ResponseValidator (response_validator.py)
    Six axes after dispatch:
        1. empty_response   — non-None, non-empty
        2. malformed        — has choices[0].message or .text
        3. tool_output      — tool_calls structurally valid (if present)
        4. finish_reason    — in accepted list
        5. reasoning_blocks — reasoning_content/thinking structurally valid
        6. message_content  — content non-empty string or valid list
    Returns ValidationResult with per-AxisResult pass/skip/fail.

RetryManager (retry_manager.py)
    Evaluates failed RequestValidator reports and ResponseValidator results.
    Strategies: token reduction (configurable factor + floor),
                provider swap (fallback_provider_id),
                model swap (fallback_model_id).
    Hard cap: max_attempts — never retries infinitely.
    Returns RetryOutcome with status, adjusted params, and reasoning.

RequestLogger (request_logger.py)
    Structured logger with bounded in-memory deque (max_records).
    Records: provider, model, token_estimate, actual_tokens, attempt_number,
             request_passed, response_passed, retry_status, issues,
             timestamp_utc, latency_ms, extra.
    API: record, recent, all_records, clear, summary_stats.
    Emits to Python logging system at configurable level.

AdaptiveCloudBrain (adaptive_brain.py)
    Top-level orchestrator. Does NOT make HTTP calls.
    Two usage patterns:
        Pattern A: prepare_and_validate(provider, model, prompt, raw_response)
        Pattern B: prep = prepare(...); caller dispatches; validate_response(...)
    Returns BrainResult with status (READY/PASSED/REQUEST_FAILED/
    RESPONSE_FAILED/RETRYING/GAVE_UP), full chain of evidence, and log record.
    All six components injectable via constructor for testing.

PART B — Runtime Introspection Engine

IntrospectableSubsystem (subsystem_interface.py)
    Abstract base class with five methods:
        status()       — SubsystemStatus (ONLINE/DEGRADED/OFFLINE/UNKNOWN)
        health()       — SubsystemHealth (status, issues, check counts, notes)
        capabilities() — List[str]
        limitations()  — List[str]
        diagnostics()  — Dict[str, Any]
    NullSubsystem: concrete stub returning OFFLINE/UNKNOWN with no capabilities.
    All methods must never raise.

SubsystemRegistry (subsystem_registry.py)
    Runtime map of name → IntrospectableSubsystem.
    Registration order preserved (Python 3.7+ insertion-order dict).
    API: register, unregister, get, require, names, items,
         all_subsystems, is_empty, clear, __len__, __contains__.
    Raises TypeError on non-IntrospectableSubsystem, ValueError on empty name.

RuntimeSnapshot (runtime_snapshot.py)
    Frozen dataclass (frozen=True) — immutable after construction.
    Fields: snapshot_id, taken_at, identity_name, identity_version,
            loaded_modules, connected_subsystems, disconnected_subsystems,
            brains, memory, runtime_health (AggregatedHealth), capabilities,
            limitations, configuration, diagnostics, subsystem_count.
    NOT connected to Cloud Brain. NOT connected to Ag.py.
    make_empty_snapshot() factory for defaults/tests.

SnapshotBuilder (snapshot_builder.py)
    Iterates all registered subsystems, calls all 5 interface methods
    defensively (try/except), aggregates results.
    Brain/memory classification via name-keyword heuristic
    (_BRAIN_KEYWORDS, _MEMORY_KEYWORDS).
    Loaded modules discovered via sys.modules with optional prefix filter.
    Health aggregation: healthy > warning > critical > unknown.
    Returns fully populated immutable RuntimeSnapshot.

IntrospectionEngine (introspection_engine.py)
    Top-level class. Owns a SubsystemRegistry and SnapshotBuilder.
    Primary method: build_snapshot() → RuntimeSnapshot.
    Optional last-snapshot cache (cache_last=True by default).
    Convenience methods: register, unregister, snapshot_summary,
    registered_subsystem_names, subsystem_count.
    Never raises — returns empty snapshot on builder failure.

INTEGRATION POINTS IMPLEMENTED
--------------------------------------------------------------------------------

[IP1] — Pass introspection_engine into process_input()

    Before: process_input(brain_input, memory, tasks, intent)
    After:  process_input(brain_input, memory, tasks, intent,
                introspection_engine=_introspection_engine,
                conversation_manager=_conversation_manager,
                entity_tracker=_entity_tracker,
                reference_resolver=_reference_resolver,
                executive_layer=_executive_layer,
                brain_dispatcher=_brain_dispatcher,
                response_processor=_response_processor,
                adaptive_cloud_brain=_adaptive_cloud_brain,
            )

    The IntrospectionEngine was already instantiated and populated in main()
    but was never passed to process_input(). Now it is. When the user asks
    introspection questions, build_snapshot() is called and the RuntimeSnapshot
    is injected as verified facts into the brain prompt — AG never invents
    capabilities.

[IP2] — Full pipeline for unknown/recall intents

    Added _pipeline_response() helper function. For every turn that resolves
    to intent="unknown" or intent="recall" (memory miss), the request now
    passes through:

        ConversationManager.build_context()
            → topic-shift detection + topic-level reference resolution
            → produces resolved_input

        ReferenceResolver.resolve(brain_input, entity_tracker)
            → entity-aware pronoun/NL reference resolution
            → "Where was he born?" → "Where was Elon Musk born?"
            → confidence-scored; only rewrites at threshold

        ExecutiveLayer.process_execution_cycle()
            → storage/category routing decision
            → informs logging; does not block execution

        BrainDispatcher.dispatch(payload)
            → standardized BrainResponse contract
            → mock adapters by default (passes through to real brain
              if mock response detected)

        ResponseProcessor.process(brain_response)
            → sanitization (strips prompt artifacts)
            → safety check
            → pending action/confirmation extraction

    Every step is wrapped in try/except. If any subsystem fails or is absent,
    execution falls through to ask_brain(brain_input) — never crashes.

[IP3] — AdaptiveCloudBrain for cloud_brain intent

    Before: ask_cloud_direct(clean_prompt) called directly.
    After:  adaptive_cloud_brain.prepare(provider, model, prompt, intent)
            is called first. This runs:
                TokenEstimator   → sets token budget before the API call
                RequestValidator → checks provider compatibility + token ceiling
                RequestLogger    → records every attempt

            The actual HTTP call is still ask_cloud_direct() — AdaptiveCloudBrain
            never makes HTTP calls itself. If prepare() raises for any reason,
            execution falls through to ask_cloud_direct() unmodified.

[IP4] — Entity tracking per turn

    After every response in main() loop:

        _entity_tracker.advance_turn()
        _extract_entities_from_text(original_input, _entity_tracker)
        _extract_entities_from_text(answer_text, _entity_tracker)
        _entity_tracker.end_turn()
        _conversation_manager.add_turn("user", original_input)
        _conversation_manager.add_turn("assistant", answer_text)
        topic = working_memory.get_topic()
        if topic: _conversation_manager.set_topic(topic)

    The EntityTracker now accumulates entities across turns. The
    ConversationManager's thread summary, recent_turns buffer, and topic
    state are updated every turn. This is what the ReferenceResolver (IP2)
    consumes to resolve pronouns in subsequent turns.

RUNTIME FLOW AFTER INTEGRATION
--------------------------------------------------------------------------------

User input
    ↓
main() loop — detect_intent()
    ↓ (unknown / recall / cloud_brain / introspection)

[introspection]
    IntrospectionEngine.build_snapshot()
    → RuntimeSnapshot injected into brain prompt
    → Cloud Brain answers from verified runtime facts

[cloud_brain]
    AdaptiveCloudBrain.prepare()
    → TokenEstimator (budget) + RequestValidator + RequestLogger
    → ask_cloud_direct(clean_prompt)
    → ResponseProcessor-safe output

[unknown / recall]
    ConversationManager.build_context()        ← topic + reference resolution
    ReferenceResolver.resolve(input, tracker)  ← entity-aware pronoun resolution
    ExecutiveLayer.process_execution_cycle()   ← routing decision
    BrainDispatcher.dispatch(payload)          ← standardized dispatch
    ResponseProcessor.process(response)        ← sanitize + safety check
    → fallback to ask_brain() if mock detected or any step fails

[end of every turn]
    EntityTracker.advance_turn()               ← turn counter
    _extract_entities_from_text() × 2         ← heuristic NER (user + AG)
    EntityTracker.end_turn()                   ← close turn
    ConversationManager.add_turn() × 2        ← update thread
    ConversationManager.set_topic()            ← sync topic
    WorkingMemory.update_working_memory()      ← existing — unchanged

  dispatch through the full pipeline, real brain adapters must be registered:

      _brain_dispatcher.register_adapter("local", LocalBrainAdapter(...))
