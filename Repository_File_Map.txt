==================================================
RUNTIME
==================================================

runtime/
    Ag.py
    runtime_adapter.py
    development_manager.py
    __init__.py

runtime/introspection/
    introspection_engine.py
    runtime_snapshot.py
    snapshot_builder.py
    subsystem_interface.py
    subsystem_registry.py
    __init__.py

Purpose:
Application entry point, startup orchestration, and runtime
infrastructure. Ag.py is the main loop and primary interface for
user interaction. runtime_adapter.py wraps every major subsystem
into IntrospectableSubsystem adapters so the health of each
component can be observed at runtime. development_manager.py is a
reserved stub for future development-mode tooling.
The introspection/ sub-package owns the snapshot and registry
machinery used to report live system health.

--------------------------------------------------

PIPELINE
--------------------------------------------------

pipeline/
    ag_pipeline.py
    __init__.py

Purpose:
End-to-end request pipeline that coordinates cognitive processing,
brain dispatch, and response delivery in a single pass.
AGPipeline assembles all subsystems and drives a user turn from
raw input to final response.

--------------------------------------------------

COGNITION
--------------------------------------------------

cognition/
    cognitive_engine.py
    control_layer.py
    executive.py
    executive_layer.py
    __init__.py

Purpose:
Higher-order reasoning and decision-making. CognitiveEngine
classifies intent, evaluates scratchpad state, and assembles the
payload for a brain call. ControlLayer manages brain selection,
authorization, and fallback chains. ExecutiveLayer interprets
category and storage decisions and builds execution plans.
executive.py holds the core ExecutiveState and analysis logic
used by ExecutiveLayer.

--------------------------------------------------

CONVERSATION
--------------------------------------------------

conversation/
    conversation_manager.py
    response_processor.py
    __init__.py

conversation/core/
    conversation_context.py
    conversation_frame.py
    entity.py
    entity_tracker.py
    thought.py
    __init__.py

conversation/cognitive/
    confidence_engine.py
    context_resolver.py
    evaluator.py
    reference_resolver.py
    response_verifier.py
    __init__.py

Purpose:
Conversation flow, turn management, entity tracking, and context
handling. conversation_manager.py orchestrates the full
conversation lifecycle. response_processor.py sanitises and
evaluates raw brain responses. The core/ sub-package holds the
data model: context state (ConversationContext), per-turn frames
(ConversationFrame), entity registry (Entity/EntityTracker), and
the reasoning object (Thought). The cognitive/ sub-package
provides deeper analysis: reference and context resolution,
cognitive evaluation, confidence scoring, and response
verification.

--------------------------------------------------

BRAINS
--------------------------------------------------

brains/
    brain.py
    brain_dispatcher.py
    local_brain.py
    token_budget.py
    __init__.py

brains/cloud_brain/
    adaptive_brain.py
    provider_registry.py
    request_logger.py
    request_validator.py
    response_validator.py
    retry_manager.py
    token_estimator.py
    __init__.py

Purpose:
Brain abstraction layer and all concrete brain implementations.
brain.py is the primary client: it provides ask_brain(), mode
switching, and the OpenAI/Ollama client wrappers. brain_dispatcher.py
routes calls to the correct adapter at runtime. local_brain.py
wraps Ollama for on-device inference. token_budget.py manages
response category budgets globally. The cloud_brain/ sub-package
implements the full adaptive cloud brain: AdaptiveCloudBrain
coordinates request preparation, validation, retry, logging, and
response validation across multiple providers, using a dedicated
module for each concern.

--------------------------------------------------

MEMORY
--------------------------------------------------

memory/
    working_memory.py
    clean_memory.py
    __init__.py

Purpose:
Working memory and in-session state management. WorkingMemory
holds all transient per-session state: objectives, tasks, topics,
facts, pending actions, reasoning notes, decision cache, and
the discussion log. clean_memory.py provides a utility to strip
ANSI contamination from persisted memory files.

--------------------------------------------------

STORAGE
--------------------------------------------------

storage/
    storage_manager.py
    schema_processor.py
    index_manager.py
    __init__.py

Purpose:
Persistent document storage with schema validation and full-text
search. storage_manager.py implements atomic CRUD operations over
JSON collection files. schema_processor.py validates and normalises
documents against versioned schemas, resolving aliases and
generating metadata. index_manager.py maintains keyword, entity,
and tag indexes over stored collections and supports ranked search.

--------------------------------------------------

DIAGNOSTICS
--------------------------------------------------

diagnostics/
    probe_simulator.py
    analytics_logger.py
    __init__.py

Purpose:
System observability and action safety analysis. probe_simulator.py
simulates proposed actions, estimates risk, detects dependencies,
and generates alternatives before execution. analytics_logger.py
records and queries runtime events (brain usage, action patterns,
topic frequencies, error events) to a persistent JSONL log.

CONFIGURATION
--------------------------------------------------

configuration/

    brain_registry.json
    memory.json
    permissions.json
    project_context.json

Purpose:
Runtime configuration files. brain_config.json controls the active
brain mode. brain_registry.json lists registered brain identities
and their metadata. permissions.json defines allowed/denied

UNCATEGORIZED FILES
==================================================

The following files exist at the repository root or in non-standard
locations and could not be confidently placed in a primary
architectural folder:

1.  D:\AG\node.exe  (92.5 MB binary)
    Reason: A Node.js runtime executable at the project root. Not
    part of the Python codebase. Likely placed here to support the
    npm/npx scripts in scripts/. Could be moved to scripts/ or a
    dedicated tools/ folder for clarity.

2.  D:\AG\.gitignore
    Reason: Repository configuration file, not a project source
    file. Standard root placement is correct.

3.  D:\AG\.aider.chat.history.md
    D:\AG\.aider.input.history
    D:\AG\.aider.tags.cache.v4\  (directory)
    Reason: Aider AI coding assistant session artifacts. These are
    tool-generated and belong in .gitignore rather than tracked
    source. Not part of the application architecture.

4.  D:\AG\platform-tools\  (directory — adb.exe, fastboot.exe, etc.)
    Reason: Android SDK platform tools. Unrelated to the Python
    project. Their presence is unexplained by the current
    codebase. Likely a leftover from a different project or an
    unrelated device-management workflow.

5.  D:\AG\__pycache__\  (root-level cache)
    Reason: Python bytecode cache at the project root, indicating
    that some source files (Ag.py, brain.py, etc.) were previously
    executed from the root before migration into sub-packages. Can
    be safely deleted.
